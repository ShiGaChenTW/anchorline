# 字級系統：盤點、收斂成階梯、可在設定調整

> 建立：2026-08-10
> 目標：把 447 個硬編字級收斂成一套階梯，整體放大一級，並讓使用者自己調。

## 盤點結果（可重跑驗證）

```bash
rg -o 'font-size:\s*[0-9.]+px' shared.css | sed 's/.*font-size:\s*//' | sort | uniq -c
```

| 指標 | 值 |
|---|---|
| `font-size` 宣告總數 | 473 |
| 硬編 px | 447 |
| 不同數值 | 21 種 |
| 用既有 token（`--text-xs`~`xl`） | **7** |
| rem | 11 |
| 半像素值 | 9.5 / 10.5 / 11.5 / 12.5 / 13.5 / 14.5 |

最常用：12px(87) · 11px(76) · 13px(73) · 12.5px(43) · 11.5px(39) · 10.5px(27)

**兩個問題**
1. **不是系統**：21 種數值、6 種半像素。`--text-xs~xl` token 早就存在卻只有 7 處在用 ——
   等於有一套規範，然後所有人繞過它。

   > 我原本要寫「半像素會被四捨五入，等於白設」。**實測推翻了**：量 25 字的字串，
   > 12px 與 12.5px 寬度差 5.7px、行高差 0.75px，確實會渲染出差別（dpr=1）。
   > 真正的問題不是「沒效果」，而是**每字差 0.23px，人眼在 UI 上分辨不出**，
   > 卻讓字級數量翻倍。差別存在但沒有價值，這才是收掉它的理由。
2. **底層太密太小**：9.5–11px 佔 128 個宣告。使用者說「設定頁字太小」就是這一層。

## 為什麼不引用 Vercel Web Interface Guidelines

有查，但**它不涵蓋字級**——只有省略號、彎引號、tabular-nums、`text-wrap: balance`
那類排版符號規則，沒有最小字級或字級階梯。Apple HIG 的字級頁是 JS 渲染，抓不到正文，
不引用記憶中的數字。所以下面的階梯依據是**現況分布本身**，不假借外部權威。

## 階梯設計

9 級，每一級都比今天對應的值大 1–2.5px（直接回應「太小」），並吃掉所有半像素。

| Token | 值 | 收攏自 | 宣告數 |
|---|---|---|---|
| `--fs-1` | 12px | 9.5 / 10 / 10.5 / 11 | 128 |
| `--fs-2` | 13px | 11.5 / 12 | 126 |
| `--fs-3` | 14px | 12.5 / 13 | 116 |
| `--fs-4` | 15px | 13.5 / 14 | 39 |
| `--fs-5` | 17px | 14.5 / 15 / 16 | 21 |
| `--fs-6` | 19px | 17 / 18 | 4 |
| `--fs-7` | 23px | 20 / 21 / 22 | 7 |
| `--fs-8` | 29px | 26 / 28 | 5 |
| `--fs-9` | 34px | 32 | 1 |

用 `calc(12px * var(--fs-scale))` 而不是 rem：rem 依賴 html font-size，
而這份 CSS 已經有 11 個 rem 字級在用，改動根字級會同時動到它們，
產生兩套互相干擾的縮放。calc 只影響掛上 token 的宣告。

## 可調整

設定 → 外觀新增「介面字級」：緊湊 0.92 / 標準 1.00 / 舒適 1.09 / 大 1.18。
走自己的 localStorage key（跟主題同一個模式），不進 settings 物件：
它必須在任何頁面第一次繪製前就套上，而 `initTheme()` 是 14 個頁面唯一的共同入口。
放進 settings 會多一條「等 store 水合完再套」的路徑，那一瞬間的字級跳動看得出來。

## 步驟

- [x] 1. 定義 `--fs-1`~`--fs-9` 與 `--fs-scale`
- [x] 2. 腳本替換 447 個硬編 px → token（只換 `font-size:`，不碰其他 px）
- [x] 3. 設定頁「介面字級」控制項 + 持久化 + 開頁即套用
- [x] 4. 驗證：半像素是否真的看得出差別（先量再宣稱）
- [x] 5. 驗證：放到最大時各頁有沒有溢出／截斷

## 結束摘要

完成。447 個硬編字級全部收進 9 級 token，設定 → 外觀新增「介面字級」四段選擇。

**實測**
- 替換數 447，與盤點數字吻合；`bunx tsc` 與 570 測試全過。
- 設定頁在 118%：無水平溢出、無非預期截斷。
- 總覽頁在 118%：無水平溢出、無非預期截斷，版面完整。
- 選擇器每個選項用**自己代表的字級**顯示樣本，不是用同樣大小的字寫「大」。

**一個誠實的非結論**
編輯台在 1200px 視窗下寫作欄只有 130px，一行剩兩三個字。看起來像字級造成的，
但量過三個倍率：0.92→138px、1.00→136px、1.18→130px。**scale 1.0 時就已經是這樣**，
字級只吃掉 6px。真正的原因是四欄版面在 1200px 沒有斷點 —— 那是另一個問題，
沒有一併修，因為它跟字級無關，混在同一次改動裡會讓兩邊都難以歸因。
