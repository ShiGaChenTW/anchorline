## 這輪學到、值得帶走的四件事

1. **要求 agent 邊做邊把結論寫進 repo 內的檔案。** 這輪六個 agent 幾乎全在交付後
   直接斷線，兩個一句回報都沒有 —— 工作沒掉的唯一原因就是這條。
   但它有邊界：**檔案保得住已完成的工作，保不住未執行的指令**（有一次指令完全
   沒被執行，是回頭 grep 檔案才發現）。每一則指派都要回頭查檔案，不看回話。
2. **source-grep 型測試的解析度到「函式」為止。** 它擋得住 Wave 1 的 F0
   （新參數只有測試在傳），但 C-1/C-3 兩條缺陷在**函式之間**，測試全綠。
   要抓那種形狀得把邏輯抽成純函式、餵時序替身。
3. **文案與行為對不上，不管往哪個方向錯都是同一個缺陷。** 這輪犯了三次
   （鈕說會破壞其實 no-op → 行為改了文案還說不生效 → 送審前預覽一份假流程）。
   解法是雙向合約測試：先跑 store 證明行為做到了，才允許斷言文案講那句話。
4. **最有價值的缺陷是使用者第一眼撞到的那個。** 「畫面沒有改」那條，當時
   tsc、1773 個測試、跨 context 審查、實機安裝全綠 —— 因為沒有任何一條測試
   同時持有「畫面顯示什麼」與「送審會建立什麼」兩邊。
