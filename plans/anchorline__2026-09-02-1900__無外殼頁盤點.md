剩下 5 個沒有外殼 —— 其中 **4 個是對的，1 個要處理**。

## 決定 1 — `landing.html` 要不要留？

**事實**（都跑過指令）：

- **不在 `vite.config.ts` 的 build input**，所以 `bun run build` 不產出它、Tauri 打包也不帶它
- 全 repo **沒有任何頁面連到它**
- 測試零引用
- 但它有真的內容：60 KB 的行銷頁，`hero` / `hero-cta`，git 上有「hero 換成治理鏈動畫演示」的 polish commit

**問題**：它是**未來的官網首頁**（現在只是還沒接上），還是**已經沒在用的舊稿**？

- 如果是官網 → 該搬去獨立的 web 專案，不該混在 Tauri app 的 repo 根目錄
- 如果是舊稿 → 刪掉

**Miles 建議**：留著，但**移進 `marketing/` 子目錄**並在 README 註明「不隨 app 打包」。
成本 10 分鐘，換掉「根目錄看起來像 app 頁但其實不是」這個誤導。

☐ 留在原地　☐ 移進 `marketing/`　☐ 刪掉

## 決定 2 — `landing-aid.html`：112 KB 的比稿副本 🔴

**事實**：

- 檔案**第 15 行自己寫著**：「這份是『拿來跟 `landing.html` 並排比較』的候選稿，CDN 版渲染結果一致就夠。」
- **112 KB，是 `login.html` 的 17 倍**，全 repo 最大的 HTML
- 不在 build input、沒人連、測試零引用
- 🔴 **含 5 處 CDN 引用**，直接違反專案硬約束「不得引入外部 CDN（離線必須能跑的 Tauri app）」

**風險不是它現在會壞，是它是顆地雷**：今天不打包所以無害，但哪天有人把它加進 build input，
離線就破了，而且**不會報錯**，只會在沒網路時版面爆掉。

**Miles 建議**：**刪掉**。比稿已經結束（`landing.html` 是勝出的那份），
要回溯隨時 `git show ed3b972 -- landing-aid.html` 拿得回來 —— git 就是它的封存。

☐ **刪掉（建議）**　☐ 留著但加 `.buildignore` 註記　☐ 先不動

## 決定 3 — 要不要補一條測試釘死這件事？

現在「哪些頁該有外殼」這件事**只活在人的腦子裡**。PRD 寫了 17，但沒有東西擋住有人手滑

成本 15 分鐘，之後這個口徑就再也不會漂。
