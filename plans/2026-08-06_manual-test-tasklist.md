# PRD開發監控台 — 人工測試 Task List（3 日版）

> **目的：** 用三個工作天跑完核心路徑，產出可執行的「調整說明」，並在最後預留「新功能規劃」區塊。  
> **測試對象：** `/Applications/PRD開發監控台.app`（正式版）  
> **建議記錄方式：** 每項勾選 + 填「結果」欄（PASS / FAIL / BLOCKED / SKIP）與備註。  
> **嚴重度建議：** `P0` 阻斷主流程 · `P1` 功能錯但有繞路 · `P2` 體驗/文案 · `P3` 美觀細節  

---

## 0. 測試前準備

| 項目 | 說明 |
|------|------|
| 環境 | macOS 11+，已安裝最新 `PRD開發監控台.app` |
| 資料 | 至少 1 個可寫入的示範專案；可接受重置本地 store 的測試帳號 |
| 帳號 | 一般員工 +（若有）管理員各一組 |
| AI（選測） | 若要測真實 AI：Settings 配好 key 或 Ollama 已啟動且模型可用 |
| 記錄工具 | 本檔 Markdown；Fail 時附截圖路徑／步驟編號 |
| 清理 | 測試開始前可截圖 Dock icon、主題狀態，避免與「預期」混淆 |

### 結果圖例

- ✅ PASS — 符合預期  
- ❌ FAIL — 與預期不符（請寫重現步驟）  
- ⛔ BLOCKED — 被其他 bug 擋住  
- ⏭️ SKIP — 本輪刻意不測（寫原因）

## 1. 建議操作流程（三天怎麼排）

整體採 **「主幹先通 → 分支補齊 → 壓測與回歸」**，避免第一天就陷在設定細節。

```text
Day 1  安裝／登入／主題／專案列表／建立與開啟
       → 目標：能穩定進編輯台並看到正確標題與 rail

Day 2  編輯台寫作、自動儲存、匯出、審閱閘門、送出與預覽
       → 目標：完整走完「寫 → 預覽 → 送審」主路徑

Day 3  設定／AI／權限與管理／狀態列／跨頁 chrome 一致性
       → 目標：非主幹但高感知功能 + 彙整調整說明 + 填新功能規劃
```

### 每日節奏（建議）

| 時段 | 做什麼 |
|------|--------|
| 前 30 分 | 重開 App、確認版本／icon／主題；瀏覽昨天 FAIL 是否仍在 |
| 中段 2–3 時 | 依當日 task 逐項打勾、截 FAIL |
| 後 30 分 | 寫「當日調整說明草稿」（現象 → 期望 → 嚴重度） |
| 結束前 | 勾選完成率；標記明日優先 P0/P1 |

### 建議主路徑（Happy Path，Day1–2 必走一次）

```text
1. 啟動 App
2. 登入
3. 專案列表：選／新建專案
4. 進入編輯台 → 改一節內容 → 確認自動儲存或狀態列有回饋
5. 預覽審閱 → 內容與章節對得上
6. （可）送出審閱 → 狀態變更
7. 切 LIGHT / DARK 各一次，確認無壞版
8. 登出 → 再登入 → 專案仍在
```
