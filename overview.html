這個軟體在做什麼

用途

Anchorline 是本機優先的開發專案工作台：寫 PRD、跑簽核、產 OpenSpec 變更文件、 取版號，並追蹤「文件說的」與「repo 做的」有沒有對上。 資料存在這台機器上，不上傳任何伺服器。

監控目的

PRD 與程式碼會分岔——規格說 A、實作變成 B，而且沒有人發現。 監控的唯一目的就是讓分岔當下可見： 哪個計劃步驟沒勾、哪個 OpenSpec change 沒收完、哪些 commit 沒有對應的計劃步驟。

監控方式

  • 唯讀掃描你綁定的專案資料夾：plans/*.md 的勾選狀態、 openspec CLI 的 JSON 輸出、git 的唯讀查詢（status／log／diff）。
  • commit 訊息裡的 anc:t=編號 錨點把 commit 對回計劃步驟—— 對不上的算「未治理」。
  • App 不會代你執行任何 git 寫入（commit／push 都是產生指令給你自己跑）。 寫入你專案的只有兩件事：你按「一鍵 openspec init」、以及下面列的 .anchorline/。

監控的檔案位置

  • 專案/plans/*.md — 計劃與勾選進度
  • 專案/openspec/ — 變更提案與規格（僅讀 CLI 輸出與 tasks 勾選）
  • git 狀態 — 未提交變更、commit 歷史（唯讀）
  • App 自己寫入的：專案/.anchorline/log/（稽核軌跡）、 專案/.anchorline/context/（專案分析報告，AI 撰寫的前置）

檔案匯出位置

  • PRD 內容平時存在 App 內部的專案資料，不落地為檔案。
  • 按「匯出 MD／HTML／備份」：桌面版寫到 專案/.anchorline/exports/（匯出完會顯示完整路徑）； 瀏覽器版落在瀏覽器的下載資料夾。
  • AI 撰寫產生的 OpenSpec 文件：下載後由你放回 openspec/changes/<id>/。
