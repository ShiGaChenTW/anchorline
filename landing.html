01 — 它解決什麼

一個開發專案工作台要回答四個問題。
多數工具答得出前兩個。

Q1
下一步做什麼？
焦點卡 · openspec 的第一個 ready artifact。欄位硬性封頂 4 個，其餘專案摺疊——一次只指一個。
Q2
現在到哪了？
plan checkbox × openspec artifact 的加權 rollup。不是把兩個百分比並排，是算成一個。
Q3
為什麼變成這樣？
決策紀錄，讀 ISA 的 Decisions / Changelog。不另存一份會分岔的 ADR。
Q4
實際發生了什麼？
append-only 稽核軌跡，JSONL，按月分片，落在你自己的磁碟上。

2026 年 ADR 復甦的理由很直白：AI agent 現在寫掉大部分程式碼，而看不到「為什麼」的 agent 會很開心地把理由重構掉。

03 — 一個市面上沒有的機制

      
authorAgentFamily
同一個 agent 族系撰寫的文件，不能由同族系核准。

      
GitHub 的 CODEOWNERS 與 branch protection 只認人，不認 AI 族系，抓不到這一類。治理鏈 replay 會把違規標出來——一條沒有標示違規的治理鏈沒有說服力。

04 — 安全界線

      
這個 App 讀得到你所有專案資料夾、會寫檔、會跑 CLI。

      
三件事都不小，所以在你看程式碼之前，先把界線講清楚。一句話：前端只能說「對哪個已授權的專案做這件已列舉的事」，不能說「用這些參數去跑這個程式」。

    


    

      

        
沒有 tauri-plugin-shell

        
allowlist 管得住「可以跑哪支程式」，管不住「參數長什麼樣」。而 git、gh、openspec 的破壞力幾乎全在參數裡。所以指令與旗標是 Rust 常數，前端能決定的只有工作目錄是哪個專案。


// exec.rs —— 前端傳不進任何一個旗標
run(&bin, &["search", "prs", "--author=@me",
             "--state=open", ...], None)

      

      

        
兩條路徑謂詞，刻意不共用

        
合併成一條「通用安全路徑檢查」是很自然的重構衝動，但那會讓 append 的嚴格度悄悄降到 editable 的水準——而降級不會有任何測試失敗，只會多出一個「可以在家目錄任何地方建 .jsonl」的能力。


append_allowed(path)
canonicalize(path) 仍在已註冊專案根目錄內   ← 擋 symlink
∧ 相對路徑第一段 = .anchorline
∧ 副檔名 = jsonl
∧ 單行 < 4KB

      

      

        
只開兩個 Tauri 權限

        
dialog:allow-open（資料夾選擇器）與 opener:allow-open-path（用系統預設程式開檔）。沒有第三個。整個原生層的設計前提是不信任前端——不是「前端應該不會亂傳」，是「前端亂傳也拿不到東西」。

      

    


    

      
永不執行

      
gh pr review --approve不可逆的對外動作。工具產生指令，人自己執行。

      
gh pr merge · pr comment同上。PR 雷達只讀，不寫。

      
git commit · push · reset同上。界線沿用 src/lib/git-doctor.ts。

      
openspec archive破壞性，會改寫真相來源。

    

  







  

    

      
05 — 明確不做

      
拒絕清單和功能清單一樣重要。

      
每一條都有理由，理由寫在原始碼的檔頭裡。

    

    

      
Kanban／拖曳／優先級／指派
Linear 的形狀，做進來就是兩套任務系統。

      
agent 派工執行
要讓原生端跑 JS 傳來的任意 prompt，等於直接拆掉整個注入防護。改成產生交接指令。

      
自建 openspec spec.md parser
上游格式會演進，自己解析等於維護一份會分岔的第二實作。這是對 OpenSpec 生態的相容承諾，不是實作細節。

      
SQLite
單人量級換不到查詢優勢，卻換來二進位進 git 與 agent 寫不進去兩個真痛。

      
PR diff 檢視器
過度專注黑洞。看 diff 去 GitHub 或 IDE。

      
雲端同步／多人伺服器
本機 + 檔案 + git 就是產品邊界。

      
瀏覽器版
降級路徑的維護成本大於價值。桌面獨佔換到少維護 19 個 guard 分支。

    

  







  

    

      
06 — 架構

      
判定邏輯一律是純函式，nowMs 一律可注入。

      
那不是潔癖。從 WKWebView 換到 Tauri 時，整個 src/lib 裡有 47 個檔一行都不用改——當初把 I/O 全推到呼叫端，代價在這裡回收。

    

    

      
47/ 57
個 lib 模組不碰原生層，可獨立測試

      
12
個 bridge action，契約凍結在 docs/BRIDGE.md

      
28
份測試檔，外加 Rust 契約測試

      
2
個 Tauri 權限，沒有第三個

    


    

      

        
為什麼是 JSONL，不是 SQLite

        

          git 可 diff、agent 用一行 shell 就能追加、壞掉的影響範圍是一行而不是整個檔。
          唯一輸的是查詢效能——而單人專案的量級（< 10 萬筆）換不到那個優勢。
        

        

          按月分片，因為 git 每次 commit 存整顆 blob；一個持續長大的單檔每天 commit
          一次會讓 repo 爆炸。合併衝突 100% 落在檔尾，所以
          *.jsonl merge=union 是一行解法。

07 — 安裝

      
目前請自行建置。

      
未簽章產物的發布流程還在做。平台：macOS · Windows · Linux——CI 三平台都建置，但目前只有 macOS 有實機驗證。

    


    

      

        

          

            bash
            
          


$ git clone https://github.com/ShiGaChenTW/anchorline.git
$ cd anchorline
$ bun install
$ bun run tauri build
  # 產物在 src-tauri/target/release/bundle/

        


        

          

            終端 TUI · 不開 App 也能用
            
          


$ bun run track      # plans/ 進度，j/k 切換，i 補鑄錨點
$ bun run backfill   # git 歷史回填成稽核軌跡（冪等）

        

      


      

        
需求

        

          
Bun≥ 1.3必要

          
Rust≥ 1.77必要

          
git任意必要

          
openspec≥ 1.6選用

          
gh任意選用

        

        

          選用的 CLI 找不到時不會報錯，畫面會顯示一行安裝提示。
          App 會依序找：你在設定裡指定的路徑 → PATH → 三平台常見安裝點。
          找不到就在設定裡填絕對路徑——任何猜路徑的邏輯都會漏掉某個人的環境。
