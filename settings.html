✍️ AI 撰寫

影響「AI 撰寫初版」與「一鍵生稿」的產出。三個欄位都可以留空 —— 留空就用內建的寫法，不會比較差，只是比較通用。

產生的內容會**填進下面的欄位讓你改**，不會直接套用 —— 這是建議，不是決定。
會併進**每一節**的 prompt。放產品脈絡、慣用語、禁用詞這類全篇適用的東西。
比任何形容詞都有效 —— 與其寫「請簡潔專業」，不如直接給一段你認可的文字。 超過 4000 字會截斷。
關閉時 AI 只補空白章節。覆蓋你已經寫好的東西是最不該預設發生的事， 所以這一項要自己打開。

各章節的 prompt 覆寫

留空 = 用內建 prompt。只有在某一節的產出一直不對時才需要動它 —— 覆寫是例外，不是預設。

團隊、流程與 AI Agent 的設定。這些是偶爾才調一次的東西，所以放在設定裡而不是側欄。

管理中心 Agent 管理

管理中心：成員、角色與審核流程。Agent 管理：AI 助教的 prompt 與進場時機。

🤖 AI 寫作教練模型與金鑰設定

必須填入 API Key 後，編輯台「一鍵生稿／語調潤色／指令」才會呼叫真實模型。未設定時按鈕會停用，不會再產生假 demo 文案。

可直接打字填任何模型 ID —— 清單只是常用捷徑，不是白名單。 供應商依開頭判斷：claude／gpt／gemini／local-smart。
需先 ollama pull 模型名。例：llama3.2、qwen2.5、mistral、gemma2
僅存本機。Gemini／Claude／GPT 需真 Key；Ollama 可任意字或 ollama。

👥 人員簽核與角色管理

管理員／核准人員／編輯人員。Agent 僅可為編輯或核准；同一 Agent 族系撰寫之文件不可由同族系核准。

切換後權限、簽核與編輯鎖定會立即生效。密碼示範皆為 demo。
