Anchorline 下一版規劃書

2026-08-14 · Grok（使用者價值）× Codex/GPT-5.4（工程）圓桌彙整 · 工程細目見 docs/NEXT-VERSION-PLAN.md

一句話總結：UAT 功能鏈已經上線，但迴圈還沒閉合——這一版先修四個「安靜的錯」 （打的字會消失、指標反向計分、報告永遠不結案、別的專案的題看不見），再把更新通道接上， 讓「換裝驗證」不再是每天的手工活。

為什麼是這幾件事

兩位評審獨立讀碼後，共同指向一個模式：這個 App 最近的問題都不是紅字錯誤， 是安靜的錯誤——數字慢慢變得沒人信、輸入無聲消失。這種錯不修，使用者會先學會「不看那個數字」， 然後功能就等於死了。

第一波 — 止血（正確性）

P0勾選時打的說明可能無聲消失

在 A 題打完失敗說明、直接按 B 題的結果按鈕——A 的說明會被磁碟舊值蓋掉，沒有任何提示。 失敗說明是整條「修復迴圈」唯一的輸入，它消失等於整條鏈白做。

Grok 原判「不會痛」；Codex 讀碼找到上一輪修 blur 競態時製造的新競態。採 Codex，動手前先實機重現。

P0愈認真用 OpenSpec，治理覆蓋率愈難看

OpenSpec 步驟的完成事件永遠對不上治理判準——每勾完一步，覆蓋率就掉一格。 App 的核心指標在對自己最推薦的工作流反向計分。修好之後歷史數字會跳一次，畫面會講清楚原因。

P0別的專案的待實測，你看不見

待實測清單只算「目前選中的專案」。Agent 幫 B 專案出的題，你人在 A 專案時 badge 顯示 0—— 錯過那一次自動喚醒，那份報告就從系統裡消失了。改成跨專案收件匣。

P1報告要能「收工」

現在報告只有「全部題目都測完」才算完成。測了 5/8 就先走的報告永遠掛在「進行中」， 待實測數字只進不出，兩週後就沒人信了。加一個人工收工／歸檔動作。

P1重測第二輪不再兩份並存

同一個功能測第二輪，新舊兩份報告都掛著、都算待實測。新報告標「重測自哪一份」， 舊的自動退場。順帶修中文標題檔名——現在全中文標題的報告檔名全變時間戳， 列表和 git 紀錄裡認不出誰是誰。

P1幾個小而準的修

側欄數字勾完就更新（現在要切走再切回）· 送出按鈕補上打字保護（同族競態）· 對話框原生層加防當機保險 · CRLF 檔案不再產生假的「檔案被改過」衝突。

第二波 — 平台

P1自動更新通道

真正的痛不是「別人裝不了」——是你每次驗證都要手動換裝， 這件事今天一天就重複了四次，還產生過一次「功能沒出現」的假 bug 報告（其實是舊版）。 先接 Tauri 的更新器（不需要 Apple 簽名），簽名等真的要對外發布再說。

P1版號流程自己用一輪

版本取號做完還沒真的走過一輪。這一版就拿它自己取號、編列、放行、PUSH—— dogfood 是唯一有時間成本的帳：愈晚開始，錯的版號愈多。

明確不做的（跟做什麼一樣重要）

項目為什麼不做
失敗截圖／語音捕捉語音要開麥克風權限、音檔還得送出機器，抵觸「資料不外流」底線；截圖會是原生橋上第一個媒體擷取權限。便宜替代：說明欄提示「⌘⇧4 截圖、貼路徑」。
一鍵複製失敗交接翻帳發現已經做完上線了，清單上是陳帳。
草稿存 localStorage會殘留跨報告的陳舊草稿；第一波的記憶體草稿層已覆蓋真實遺失路徑。
掃描快取（完整版）現在每秒 364 KB 還不痛，快取誤判反而會讓畫面停在舊內容。先只撿免費的（刪一次重複的檔案查詢）。
Apple 簽名單機單人，簽名解的是散佈問題——那個場景還不存在。
011 願景欄位擋送審單人簽核下 gate 是自我約束；等你裁決要不要多這道門。

建議順序

說明遺失 → 按鈕保護 → 中文檔名 → 重測退場 → 收工歸檔 → 跨專案收件匣 → 治理計分修正 → 側欄數字 → 可測性（AX）→ 對話框保險 → CRLF → 更新通道。版號 dogfood 從第一個 commit 就開始， 整波結束正好放行一版。
