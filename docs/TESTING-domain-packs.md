# 手動測試流程 — 領域包

> 對象：`Anchorline Test.app`（測試變體，資料與正式版分開存，不會互相污染）
> 目的：補上自動化測試蓋不到的部分 —— **桌面才有的資料夾存取**，以及**設定頁的 UI 接線**

自動化已經蓋住的不用再手測：規則直譯（46 條）、領域包解析與繼承（64 條）、
章節骨架／標記分離（12 條）、AI 產出的驗證閘門與重試迴圈（16 條）。
下面每一項都是**只有真的點下去才知道**的。

`/Applications/Anchorline Test.app` 丟到垃圾桶。

## 5. AI 協作產出領域包 ← **這段是這次唯一沒實機驗過的**

需要先在 **偏好設定 → AI 寫作教練模型與金鑰設定** 填好金鑰並儲存
（Gemini / OpenAI / Anthropic / 本機 Ollama 皆可）。

展開 **偏好設定 → 領域包 → 「用 AI 產生一個領域包」**。

**5a 範本下載**

- [ ] 點「下載空白範本」→ 瀏覽器下載 `domain-pack-template.md`  &gt; 點擊按鈕沒用
- [ ] 打開它，內容是註解完整的範本（四種 predicate 都有示範） &gt; 下載沒啟動,所以沒測試到

**5b 產生**

- [x] 描述欄留白或只打三個字 → 點「產生」→ 出現紅字「描述太短…」，**不會**發出請求  
- [x] 沒填金鑰時點「產生」→ 紅字提示先去設定金鑰，**不會**發出請求
- [x] 貼下面這段描述 → 點「產生」

```
台灣的線上證券下單 App。必須涵蓋證券商管理規則的委託人身分確認、
逐筆交易的洗錢防制監控、以及當沖與信用交易的風險預告書。
交易糾紛多半出在成交回報與委託紀錄對不起來。
```

- [x] 按鈕變灰、狀態列顯示「產生中…」
- [ ] 產出區出現，狀態列顯示「已產生「…」（N 個章節）」 &gt; 出現“產生失敗：修正後仍無法解析：AI 產出：缺少 --- frontmatter ---”,但有產出內文
- [ ] 如果顯示「第一次驗證未過，已自動修正」——**那是正常的**，代表重試機制有作用 &gt; 沒有出現

**5c 迭代**

- [x] 在「要改哪裡？」輸入：`把當沖那條改成 warn，另外加一段成交回報對帳`
- [ ] 點「依指示重產」→ 產出更新，且能看出照著指示改了 &gt; 出現“產生失敗：修正後仍無法解析：AI 產出：缺少 --- frontmatter ---”

**5d 手改後仍受檢**

- [ ] 直接在產出的文字框裡，把某條規則的 `section:` 改成一個不存在的名字 &gt; 出現“產生失敗：修正後仍無法解析：AI 產出：缺少 --- frontmatter ---”
- [ ] 點「加入我的領域」→ 紅字「還不能加入：規則 … 指向不存在的章節 …」 &gt; 出現“產生失敗：修正後仍無法解析：AI 產出：缺少 --- frontmatter ---”
- [ ] 改回去 → 再點「加入我的領域」→ 成功 &gt; 無法測試

**5e 落地  &gt; 請你幫忙測試**

- [ ] 若前面已指定過領域包資料夾 → toast 說「已寫入領域包資料夾：xxx.md」，且**該檔真的出現在資料夾裡**
- [ ] 若沒指定資料夾 → toast 說「只存在這台瀏覽器，建議下載後放進資料夾」
- [ ] 點「下載 .md」→ 檔名是包的 `name` &gt; 沒有反應
- [ ] 回編輯台 → 下拉選得到這個新領域，章節與 gate 都在

> 🐞 5e 那條「寫進資料夾」很重要：如果只留在記憶體，開了自動重掃之後
> 下次開 App 它就會消失 —— 那是最難查的一種資料遺失。
